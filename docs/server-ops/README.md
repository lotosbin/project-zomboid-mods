## 3. 外部存活检查（不需要凭据）

```bash
scripts/check_server_online.sh              # 默认查 110.42.14.5:21217
scripts/check_server_online.sh <ip>:<port>  # 查别的地址
```

退出码 `0`=已登记 / `1`=未登记 / `2`=请求失败。它读 Steam 主服务器登记表，
**不返回**在线人数、地图、模组列表——那些走 §2 的 RCON。

```bash
curl -s "https://api.steampowered.com/ISteamApps/GetServersAtAddress/v1/?addr=110.42.14.5"
# 该主机上登记着 33 台 PZ 服（2026-10-13 实测）；21217 在列，16261 不在
```

### 3.1 `steamid` 不是固定身份（同一地址两个时刻两个值）

| 读数时刻 | `steamid` | 采样 |
| --- | --- | --- |
| 2026-10-13 07:47–07:50 | `90294690668413958` | 4 次一致 |
| 2026-10-13 20:09 | `90294719523630086` | 4 次一致 |

地址、端口、AppID、`secure` 全程没变，**只有 `steamid` 变了**。
**不要**把它当服务器身份写进文档或对外文案；**推测（未证实）**它随进程重新注册而变，
可能是一条免凭据的重启信号，但两次观测隔了 12 小时，分不清重启次数，暂不当结论。

### 3.2 我这边跑不通的手段（别人跑得通，见末行）

| 手段 | 结果 | 结论 |
| --- | --- | --- |
| `ping 110.42.14.5` | 3/3 回包，51–94 ms | 主机在线，与游戏服状态无关 |
| `nc -z 110.42.14.5 <port>` | 21217 / 16261 / 12345 / 9999 / 80 / 443 / 22 **全部** succeeded | 前面有中间盒对任意 TCP 端口应答，**TCP 探测在该主机上无判别力** |
| A2S_INFO（我写的探针） | 只回 `ff ff ff ff 41 <challenge>`，带上 challenge 再问**仍然**只回 challenge | **是我的探针有问题**：同一天内 @QQ运营 / @小红书运营 / @哔哩哔哩运营 各自独立拿到了名字、地图、`0/32`，且与 RCON 实测的 `PublicName` / `MaxPlayers=32` **三处吻合**。这一格不许再写"不能拿 A2S 读数" |

> 两条教训：① 在开着的端口比关着的还多的主机上，`nc -z` 通过/不通过都不是证据；
> ② **同一个人复现不出来，不等于这件事做不到**——先看别人的读数有没有被独立证据交叉验证过。

时间线（`WorkshopItems`/`Mods`，来自本地保留的各版配置）：

| 版本 | 工坊条目 | 模组 |
| --- | --- | --- |
| `-0929` | 165 | 188 |
| `-1004` | 167 | 190 |
| `-1005` | 175 | 198 |
| `-1009` | 175 | 199 |
| `-1012` | 177 | 200 |
| **线上现值** | **185** | **209** |

两个数是**两层**：`WorkshopItems` 是"服务器要求订阅的工坊条目"，
`Mods` 是"要加载的模组 id"——一个工坊条目可以含多个模组，所以 `Mods` 恒大于 `WorkshopItems`。

**别再引用本文档早期那个 165**：它是 **2026-09-28/09-29 的快照**，来源是客户端连服日志
`ConnectToServerState: onItemQueryCompleted numResult=165`（`docs/server-ops/mod-snapshot-2026-09-28.txt`）。
两个独立来源（连服日志的 165 与 `-0929` 配置的 165）互相印证，所以那个数没错——**只是过期了**。

对外可以说「一百多个工坊条目、还在加」；要写死就写 **185**（带日期）。
