## 2. 外部存活检查（不需要服务器凭据）

Steam 主服务器接口会列出该地址上登记在册的 PZ 服务器，这是目前**唯一**一条在本机跑通、
不依赖任何服务器凭据的存活信号：

```bash
scripts/check_server_online.sh              # 默认查 110.42.14.5:21217
scripts/check_server_online.sh <ip>:<port>  # 查别的地址
```

底层就一条请求：

```bash
curl -s "https://api.steampowered.com/ISteamApps/GetServersAtAddress/v1/?addr=110.42.14.5:21217"
# {"response":{"success":true,"servers":[{"addr":"110.42.14.5:21217","steamid":"<每次会话可能不同>",
#  "appid":108600,"gamedir":"zomboid","region":-1,"secure":true,"lan":false,
#  "gameport":21217,"specport":0}]}}
```

**这条信号的局限（别过度解读）：**

- 它读的是 Steam 主服务器的登记表，服务器掉线后**不会立刻**从表里消失，延迟未知。
- 它**不返回**在线人数、地图、模组列表。要看这些必须走 §4 的凭据通道。
- 它只能证明「这台机器在 Steam 上登记为 PZ 服务器」，**不能**证明玩家此刻进得去。

### 2.2 `steamid` 不是固定身份（2026-10-13 实测，同一个地址两个值）

| 读数时刻 | `steamid` | 采样 |
| --- | --- | --- |
| 2026-10-13 07:47–07:50 | `90294690668413958` | 4 次，值一致 |
| 2026-10-13 20:09 | `90294719523630086` | 4 次，值一致 |

地址、端口、AppID、`secure` 全程没变，**只有 `steamid` 变了**，且每个时刻内部稳定。

- **不要**把 `steamid` 当成服务器身份写进任何文档或对外文案——它会在会话之间变。
  （本文档 20:07 那一版把它当固定值写进了 §1，20:10 已改掉。）
- **推测（未证实）**：它随服务器进程重新注册而变，因此**可能**是一条免凭据的"服务器重启过"信号。
  目前只有两个时刻的观测，中间隔了 12 小时，无法区分"重启一次"和"重启多次"。
  要坐实需要**盯一次已知的重启**（重启前后各采几次），在那之前只能当候选信号，不能拿去判断可用性。

### 2.1 试过但不可用的手段

| 手段 | 结果 | 结论 |
| --- | --- | --- |
| `ping 110.42.14.5` | 3/3 回包，51–94 ms | 主机在线，但和游戏服状态无关 |
| TCP 端口探测 `nc -z 110.42.14.5 <port>` | 21217 / 16261 / 12345 / 9999 / 80 / 443 / 22 **全部** "succeeded" | 明显有中间盒/防护设备对任意 TCP 端口应答，**TCP 探测在该主机上没有任何判别力** |
| A2S_INFO（Valve Source 查询）UDP 21217 | 任何一个 UDP 包都收到固定 `ff ff ff ff 41 <4 字节>`；带上它给的 challenge 再问，**仍然**只回 challenge | 探测包大概被中间盒截下了。**不能**用 A2S 拿在线人数 |

> 教训：在开着的端口比关着的端口还多的主机上，`nc -z` 通过/不通过都不是证据。

## 5. 尚未拿到、需要人给的东西

以下每一条都只能由服务器持有人提供，并且决定了运营能做什么：

   没有 RCON 就只能靠人肉进服务器打字，做不了自动广播、踢人、存档。
3. **存档与备份**：`Zomboid/Saves/Multiplayer/<存档名>` 在哪台机器上、多久备份一次、谁负责。
4. **线上配置原文**：`<服务器名>.ini` 的 `Mods=` / `WorkshopItems=` / `PublicName` / `PublicDescription`
   与 `_SandboxVars.lua`。模组清单已由 §4 的日志快照代偿，但**沙盒参数、PVP/PVE、白名单、
   人数上限**仍然只能看这份原文。
