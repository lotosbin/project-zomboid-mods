## 三、改进项（我直接改的 + 需要人做的分开）

### 3.1 我改的：两条可执行的规矩（写进本文件即生效，第 4 节有落点）

**规矩 A —— 回读纪律（治四起事故的病根）**

一个状态一旦被读出来，**它的有效期到"我下次重新读它"为止**，不是到"这次对话结束"。
具体到动作：

| 场合 | 必须做的 |
|---|---|
| 引用**会变的线上状态**（版本号、审核态、在线数、工坊描述）前 | 重读一次权威来源，并在消息里写明**读数时间**（例：`acf timeupdated=1791812609`）；写不出时间的数字不许用 |
| 下"现在是什么状态"的结论前 | 若上一次读数是**几分钟前**，视为无效，重读 |
| 任何**写操作**（点发布、点上传、改线上内容） | ① 动作前：确认目标唯一（见规矩 B）；② 动作后：**回读目标状态**才算成功 |
| 上报"已完成" | 必须能写出**回读到的**证据（计数 122→123 / 分页签 / `?published=true`），不能写"已点按钮" |
| **写"因为 X 所以 Y"这种机制、因果、跳转链**（A3） | 要么复现两次以上，要么写明是谁在什么上下文下观测到的。**单次观测不许写成机制** |

> A3 的由来：本文件初版把"`curl` 会 301 到 `/opus/…`"当机制写下来（实际那是浏览器/WAF 层的一跳，
> curl 只补斜杠），**在被 @哔哩哔哩运营 指出后复现才发现**。
> 规矩写出来不到一小时，写它的人就违反了它——所以这条必须落在文档上，不能靠记性。

**规矩 B —— 浏览器操作纪律（治 2.1 + 2.2）**

1. **一个目标，一个专属标签页**：动手前先导航到目标页并确认标题/URL 是自己要的那一个；
   别人的标签页一律不碰（本次误触的成因）。
2. **同名按钮禁止按文字点**：页面上存在多个「发布」时，必须用能穿 shadow root 的路径
   （macOS 辅助功能树 `AXPress`，已封进 `小红书分享/发布笔记.js` 的 `pressPublishViaAX()`），
   不许再用 JS 按 `innerText` 找按钮。
3. **状态词统一四态**，所有人只用这四个：
   `已提交 / 审核中 / 已公开（附链接）/ 已有数据`。
   要表达"审核中"就必须写**读到它的时间**；说不清就重读。
4. **授权 ≠ 操作**：`@human 说发` 是授权，点按钮是操作者的动作。排期表里不许出现
   "等人点按钮"这种步骤。
