## 三、改进项（我直接改的 + 需要人做的分开）

### 3.1 我改的：两条可执行的规矩（写进本文件即生效，第 4 节有落点）

**规矩 A —— 回读纪律（治四起事故的病根）**

一个状态一旦被读出来，**它的有效期到"我下次重新读它"为止**，不是到"这次对话结束"。
具体到动作：

| 场合 | 必须做的 |
|---|---|
| 引用**会变的线上状态**（版本号、审核态、在线数、工坊描述）前 | 重读一次权威来源，并在消息里写明**读数时间**（例：`acf timeupdated=1791812609`）；写不出时间的数字不许用 |
| 下"现在是什么状态"的结论前 | 若上一次读数是**几分钟前**，视为无效，重读 |
| 任何**写操作**（点发布、点上传、改线上内容） | ① 动作前：确认目标唯一（见规矩 B）；② 动作后：**回读目标状态**才算成功 |
| 上报"已完成" | 必须能写出**回读到的**证据（计数 122→123 / 分页签 / `?published=true`），不能写"已点按钮" |
| **写"因为 X 所以 Y"这种机制、因果、跳转链**（A3） | 要么复现两次以上，要么写明是谁在什么上下文下观测到的。**单次观测不许写成机制** |
| **凡是"估"出来的数字**（语言数、条目数、覆盖数） | 要么写**实测值 + 复算命令**，要么标明"这是估的"。**不许把估的写成数的** |

> A3 的由来：本文件初版把"`curl` 会 301 到 `/opus/…`"当机制写下来（实际那是浏览器/WAF 层的一跳，
> curl 只补斜杠），**在被 @哔哩哔哩运营 指出后复现才发现**。
> 规矩写出来不到一小时，写它的人就违反了它——所以这条必须落在文档上，不能靠记性。

> **同一类病的更多实例（当天陆续出现，都是"回读"抓出来的，记下来证明这不是一次意外）**：
> - **B 站动态：点「发布」不等于发出**——网页端还会弹一个「确认并发送」的规范弹窗，必须再点它才落库。
>   @哔哩哔哩运营 第一次点完「发布」后接口里查不到新动态，靠**回读**发现（工具 `控制台/发动态.js --send` 已补这一步）。
> - **列表接口不下发正文**：`x/polymer/web-dynamic/v1/feed/space` 对图文动态不含 `desc.text`，
>   只看列表会把一条有内容的动态**误判成空动态**——"读到了空"和"本来就是空"是两回事。
> - **"28 种语言"是估的不是数的**：@bin2_extension_mod_dev 写 §14.12 时只看了一眼目录数量就下结论，
>   实测是 **25 / 25 / 29**（缺 `AR`/`NL`/`PT`/`UA`）；他**自己发现并改成实测值 + 复算命令**（commit `227ce1f`）。
>   这条的正面意义：**把命令写进文档，下一个人能复算，而不是只能信作者**。
> - **"网页是空壳"被我当成"内容看不到"的证据**：B 站动态正文由 JS 拉，壳页本来就不渲染正文，
>   **壳页渲染与否和内容可不可见是两件事**；准确口径是"离开浏览器核不到，原因是风控不进门"。
>   我自己写文档时的表述比执行者更绝对，**是他复议后订正的**。这与 A3 同源：**把观察到的现象直接当结论**。
> - **"✓ 备好了"与"发布按钮在不在辅助功能树里"是两件事**：作者自检报"备好了"，我用他给的**只读**命令读页面，
>   四项内容（图 4 / 标题 / 正文 629 字 / 话题齐）都对，**但工具自己在 AX 树里找不到「发布」按钮**，
>   判"页面没备好或按钮此刻不可点"。**内容就绪 ≠ 目标可达**——所以那时按"发"没有落点。
>   这条正好落在规矩 B 第 2 条上（**目标唯一且可达才允许按**），也是"回读要读对东西"的实例：
>   读了内容、没读可达性，结论就会偏。
> - **一条会给出假阴性的命令，比没有命令更危险**：复核"改写前版本在不在对象库"时，
>   `xargs -n 300 git cat-file --batch` **本身是坏的**（`fatal: batch modes take no arguments`），
>   管道里没有内容，`grep -c` 于是返回 **0**——看起来像"证据表明不存在"，实际是**命令没跑起来**。
>   **第二条同类坑：locale**——`LANG=C.UTF-8` 下普通 `grep -ac` 对含 NUL / 非 UTF-8 字节的对象流返回 **0**，
>   加 `LC_ALL=C` 才是 **1**（python 字节计数同为 1）。**仪器坏了会伪装成结论。**
> - **我当天第二次犯 A3（自己写的规矩，自己违反）**：我把**相隔 54 秒**的两条读数（工具 10:45:44 / 窗口实况 10:46:38）
>   拼起来，断言"工具所指的窗口和 Safari 实际窗口不是一回事"这个**机制**。被 @bin2_extension_mod_dev 驳回：
>   那期间**窗口数本身在变**（4→3→2，窗口在关），"目标走了"与"工具指错窗口"两种解释都成立；
>   而我读了 `activatePublishTab()` 的实现后确认——**代码按当前标签页 URL 定位窗口、切换后重扫当前序号、找不到返回 `0|`**
>   ——**这条代码事实是反对我那个断言的**。**跨时刻的读数不能互证机制**；文档已改成"未定"。
>   代价说明：把没取证的机制写进文档，会让下一个人**去修一个可能不存在的 bug**，比没有结论更坏。
>
> 这几处加上第一节那四起，都是同一句话：**操作或观察返回的那个"成功"、那个数字、那个"空"，不等于状态真的变了**。

**规矩 B —— 浏览器操作纪律（治 2.1 + 2.2）**

1. **一个目标，一个专属标签页**：动手前先导航到目标页并确认标题/URL 是自己要的那一个；
   别人的标签页一律不碰（本次误触的成因）。
2. **同名按钮禁止按文字点**：页面上存在多个「发布」时，必须用能穿 shadow root 的路径
   （macOS 辅助功能树 `AXPress`，已封进 `小红书分享/发布笔记.js` 的 `pressPublishViaAX()`），
   不许再用 JS 按 `innerText` 找按钮。
3. **状态词统一四态**，所有人只用这四个：
   `已提交 / 审核中 / 已公开（附链接）/ 已有数据`。
   要表达"审核中"就必须写**读到它的时间**；说不清就重读。
4. **授权 ≠ 操作**：`@human 说发` 是授权，点按钮是操作者的动作。排期表里不许出现
   "等人点按钮"这种步骤。
