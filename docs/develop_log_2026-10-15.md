## 一、结论：今天全队收敛到同一句话——「没有」和「没读到」不是一回事

10-15 没有发布、没有事故，主线是**证据的留存方式**。三条线索各自独立地指向同一件事：

1. **采样器改留原始字节**（服务器运营 `494a113`）。起因是同一个人的同一个名字，QQ 线 10:41 读到 `c0bb450162696e32`、
   10:50 读到干净的 `62696e32` ⇒ **前 4 字节是传输层产物、不是名字的一部分**。
   关键理由：**采样是无人值守跑的，先解码再落盘就等于把原始字节丢了、回头补不回来**（人可能已下线）。
   ⇒ **证据必须在产生的那一刻无损留存**，不能事后凭记忆重述。末列转义也是必须的（`players` 应答带换行会把后面所有行错位；桩测过）。
2. **我这边的同一条**（10:32，账本 `8942b05`）：小红书三篇的"0 条"其实是**未报数**——同一份内嵌 JSON 里，
   征求帖是 `commentCount: "13"`（有数），造纸篇是四个计数**全空串**。⇒ **空串的语义是「这页没报数」，不是 0**。
   更硬的一条来自渠道实测：同一条链接、**同一个 token** 读到 0 且页面自报「(无)」，**换现取的新 token 立刻又是 13/13**
   ⇒ **"没渲染"长得和 0 一模一样**。
3. **服务器侧的同一句**：13/13 应答、服务器全程在 Steam 登记表内 ⇒ **今晚的 0 是"没人来"，不是"没读到"**；
   而 RCON 也会**偶发返回空**（11:16 一次 `showoptions` 落 0 字节、重跑正常）⇒ **"空输出"与"0 人"必须分开**。

一句话总结今天的口径增补：**数字要么有出处，要么写「未报数」；"空"和"0"、"没读到"和"没有"，在任何一层都不能混。**

## 三、两处结构性问题（今天看得更清楚）

### 3.1 「职责在，权限不在同一个人手上」

线上**没有任何自动备份**，现在是确定的（RCON 实读 `BackupsPeriod=0` / `BackupsOnStart=false` /
`BackupsOnVersionChange=false` / `BackupsCount=1`（默认 5，被设成最小值）/ `SaveWorldEveryMinutes=0`）
⇒ **不产出任何备份文件 ⇒ 出事后没有可回滚的东西**，而"回档"是明写的一项职责。
两个触发开关是**主动关掉的**、`Count` 取了最小值 ⇒ 看得出当初是**特意关的**（常见理由是备份占满盘），
所以改之前要知道为什么。
**最小改法**已给出（只开 `BackupsOnStart=true` ＋ `BackupsCount` 给 1–2），但**改的人得有服务器文件访问权限**
（他手上只有只读 RCON、`~/.ssh/config` 里也没有这台主机）⇒ **已经提给需求方拍板**。

- 这条与我一直记的「产出 → 提交 → 通知」是**同一族的第三个面孔**：**能改的人不知道要改，知道要改的人改不了。**
  10-13 是"做完了没人知道"，10-14 是"产出没有默认落点"，今天是"**职责与权限不在同一个人身上**"。
- 我记的边界：云厂商层面的磁盘快照我看不到；**若存在，那是另一条回滚路径，但不当成"有备份"**（这句是他写的，我照收）。

### 3.2 「结论对」不能用来免责「理由是编的」

他 11:13 那句话的**结论碰巧不变**（本机确实没有线上副本、他确实没有管理通路），但他照样当天收回，
理由写得很干脆：**用一个字段的差异推出了过强的结论**——"和我一直提醒渠道的『单点读数不构成证据』是同一个错，只是换我自己犯"。
我把这条采纳为口径，因为它正是我 10-14 犯过的同一类（我把接口的 `-352` 放大成"裸 HTTP 一律"）。
