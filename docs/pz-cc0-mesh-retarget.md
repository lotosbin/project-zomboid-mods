# 把 CC0 动物网格搬到 Project Zomboid 的骨架上（逐骨骼仿射传递 + 逆蒙皮烘焙）

场景：**给一个已发布的 PZ 动物模组换模型**，但必须保留它自己的骨架与动画剪辑
（引擎按动画集的名字播剪辑、附件挂在固定骨骼上、ModData 里存着动物类型），
所以"换模型"只能是"把别人的网格搬进现有骨架的绑定空间"，不能连骨架一起换。

本文是可复现的做法与两个真实踩过的坑，实现见
`bin2_companion_alpaca/tools/alpaca/build_alpaca_from_cc0.py`（本项目用它把
[Quaternius 的 CC0 羊驼](https://poly.pizza/m/bCVFD48i2l)（Public Domain / CC0 1.0）
搬到 [Companion Dogs](https://steamcommunity.com/sharedfiles/filedetails/?id=3740052292) 的 Raccoon 骨架上）。

## 0. 为什么不能"直接把网格拉成想要的形状"

第一版做法是**程序化重塑现成的犬体模型**（拉长脖子、拉长腿、立耳、加绒面噪声，见
`derive_alpaca.py`）：轮廓能大致像羊驼，但头骨、吻部、躯干断面仍是犬科底子，
用户一眼就否掉了（"模型与羊驼差别太大"）。**要像，就得换几何来源。**

## 1. 记号

* 目标骨架（要保留的）：骨骼 `b`，静止世界矩阵 `Wn(b)`，绑定逆矩阵 `IBM_dog(b)`，
  定义蒙皮矩阵 `D_b = Wn(b) · IBM_dog(b)`；顶点在**绑定空间**。
* 来源模型：骨骼 `β`，其"自然姿态 P"下的世界矩阵 `Wc_P(β)`，`IBM_cc0(β)`，
  定义蒙皮矩阵 `S_β = Wc_P(β) · IBM_cc0(β)`；顶点也在**绑定空间**（glTF 规定蒙皮结果
  就是 `Σ w·(jointWorld·IBM)·v`，与网格节点的变换无关）。

## 2. 步骤

1. **合并来源网格**：Quaternius 的 glb 按材质拆成 7 个 primitive 且没有 UV/贴图；
   合并成一个 primitive 并记下每个三角形的材质号（后面画图集要用）。
2. **骨骼对应**：两套骨架名字/拓扑完全不同，所以写一张**显式表**（本项目 46 项全覆盖），
   兜底用归一化位置最近邻。注意把**带权重的辅助骨**（IK/pole）也映射掉，否则那部分顶点会掉到默认骨头上。
3. **全局相似变换**：来源是 FBX 转出来的，**动画世界坐标比绑定姿态大约 100 倍**（cm/m），
   根节点还带 `-90°X`。所以先用 Umeyama 在"来源姿态 P 的关节位置 ↔ 目标静止姿态的关节位置"
   上求 (scale, R, t)，得到 `G`。不做这步，尺度会差 10 倍以上。
4. **目标形状**：`p_target = Σ w·(G·S_β)·v`（按来源模型自己的蒙皮权重混合）。
5. **逆蒙皮烘焙**（关键，见 §3）：解 `v_bind = (Σ w·D_b)⁻¹ · p_target`。
6. **法线**：先由 `p_target` 重算，再乘 `(Σ w·D_b)⁻ᵀ` 预补偿，使运行时按 `Σ w·D_b`
   变换后正好得到目标法线。
7. **UV/贴图**：来源没有 UV，就按三角形拆独立 UV 岛（每格一个三角形），
   格内按材质分类上色（皮肤三档 → 毛色亮/主/暗，鼻镜/蹄/眼固定），再叠程序化绒毛场。

## 3. 坑一：混合仿射算位置 + 引擎再混合权重 ≠ 可逆

**症状**：静止姿态完全正常，一动起来（或静止也一样）网格裂成"一地碎瓷片"——
每个三角形像独立的小板子，缝隙处能看到背景。

**原因**：我先用 `Σ w·(D_b⁻¹·G·S_β)` 求顶点位置（一组权重），
又让引擎用 `Σ w'·D_b` 去变换它（`w'` 是另一组权重，哪怕相同也一样）。
`Σ w·D_b` 与 `Σ w·D_b⁻¹` **不是互逆运算**（混合与求逆不可交换），
于是每个顶点都留下一个方向不同的残差 ⇒ 表面被撕开。

**正解**：先定死目标形状 `p_target`，再**解**绑定坐标
`v_bind = (Σ w·D_b)⁻¹ · p_target`（逐顶点 4×4 求逆，本项目 4156 个顶点全部精确解出）。
这样运行时 LBS 在静止姿态**精确复现**目标形状，动画时按骨骼相对运动形变。
矩阵病态时（`|det| < 1e-12` 或 `cond > 1e6`）兜底用权重最大的那根骨头求逆。

另一个容易忽略的细节：**落地偏移要加在目标形状上再重解**，
不能给绑定坐标加平移 —— `Σ w·D_b·(v + c) ≠ (Σ w·D_b·v) + c`。

## 4. 坑二：权重平滑会把相邻肢体的权重互相扩散

来源模型的权重是作者按解剖画的，本身可用。我一开始为了"让关节更顺"做了 3 轮网格邻接平滑
（alpha 0.55），结果**腿和尾巴在动画里被撕开**：平滑沿网格面扩散权重，
把腿的权重糊到了躯干、把尾巴的权重糊到了臀腿。
默认改成**不平滑**（`--smooth-iters 0`），需要时只做 1 轮、alpha ≤ 0.25。

## 5. 验证手法（没有游戏也能做）

* **离线蒙皮渲染器**（`render_glb.py`）：先渲染**来源模型自己的 Idle 姿态**当作"形状基线"
  （确认它本身是好的），再渲染传递结果；随后逐剪辑（idle/walk/run/eat/attack/rest）目视
  确认"不冻结、不碎裂、脚踩地"。
* **数值断言**（`validate_glb.py`）：骨骼 ≤ 60、21 个必需 `Rac_*` 剪辑、accessor 不越界、
  POSITION min/max 与数据一致、**带蒙皮权重的骨骼平移通道不得爆值**（共享 accessor 双重叠加的回归）、
  有 `TEXCOORD_0`、顶点数是 3 的倍数、索引是 `0..N-1` 连续序列。
* **残差诊断**：Umeyama 拟合后打印每根骨的残差（本项目最大的是无权重 pole 目标骨与
  `Body→Spine_01`；后者提示两套骨架的躯干分段不同，属于可接受误差）。

## 6. 授权

只用 **CC0 / Public Domain** 的模型来源（poly.pizza 页面上标注 `Public Domain (CC0)`，
页内 JSON 也是 `"Licence":"CC0 1.0"`），并把原件、直链、sha256 一起入库
（`tools/alpaca/vendor/`），在 `CREDITS.txt` 写清"用了什么、改了什么、没用它的什么（骨架/动画）"。
目标模组自己的骨架与剪辑按它的 addon 授权条款使用。

## 7. 姊妹坑：改静止位移必须同步改**剪辑通道**（硬绑定模型才会暴露）

2026-10 做"方块羊驼"（`bin2_blocky_alpaca/`，脚本生成 23 个长方体、每顶点 100% 绑一根骨头）时踩到的：

**症状**：静止渲染完美，一播动画（walk/eat）整只动物散架，方块各飞各的。

**根因**：base 的 glb 里**每条剪辑对每一根骨头都有位移轨道**（实测 55 骨骼 × 23~24 条通道）。
运行时 glTF 动画的位移轨道会**覆盖**节点自身的静止位移，所以"只改静止位移"的模型
在静止视图里完全正常、一播动画就被打回剪辑里的旧位置。

**修法**：位移增量必须**同时写进该骨骼在所有剪辑里的位移通道**（本项目的做法与 base 自己的
骨长调参函数一致：`derive_alpaca.apply_bone_lengths` 就是 rest + 全部动画通道一起改；
注意每根骨骼的通道要拆成独占 accessor，见 §坑一 里的共享 accessor 问题）。
此外要**只改位移、不改旋转**：改旋转会连带改变动画的摆动方向（旋转轨道同样会覆盖，
但父级静止旋转会参与子级的坐标系换算）。

**为什么写实网格不容易发现**：写实网格是权重混合的，静止位移被覆盖只会让网格被"拉伸"，
被身体挡住看不出来；而硬绑定（每顶点单骨骼）的方块是刚体，位移一错立刻分家。
反过来说：**硬绑定是检验"骨架/动画是否真的一致"的探针**。
