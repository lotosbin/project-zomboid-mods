# 社区建议汇总

**唯一入口。** 无论谁在哪个社区征求建议（B 站 / 小红书 / QQ 频道 / QQ 群 / KOOK / Steam 工坊），
回收都只落在这一个文件里。目的只有一个：**让"收到了什么、谁处理"有据可查**——散在四个平台评论区的建议等于没征求。

## 怎么记

一行一条，追加在下面的表里，不要开辟第二个文件：

| 日期 | 渠道 | 建议（原文摘要） | 出处 | 状态 | 归属 |
|---|---|---|---|---|---|
| … | … | … | 链接或文件路径 | 待评审 / 已采纳 / 已拒绝 | 见下 |

- **出处必须有**：链接（带必要参数，例：小红书链接必须整条带 `?xsec_token=`）或本地素材路径。
  写不出出处的条目**不许进表**——那和"我听说有人想要"没有区别。
- **状态只有三态**，并且要能追下去：
  - `待评审`：还没人看过。
  - `已采纳`：**必须指向去向**（任务 id / commit / PR），否则不算采纳。
  - `已拒绝`：**必须写理由**，并且理由要能对上《接/不接判据》里的某一条闸（见下节）。
- **归属是独立的第六列，不要塞进状态**（2026-10-13 定）。理由：`待归属` 与三态是**两个维度**——
  一条建议可以既"待评审"又"受归属阻塞"，也可能"已采纳"却卡在没人提交。混成一列，状态机迟早会漂。
  取值：
  - `bin2_extension` → @bin2_extension_mod_dev 负责，**24 小时内**给「接/不接 + 理由 + 粗估工作量」。
  - `bin2_npc_extension` → **归属已于 2026-10-13 解决**：v0.5.0 由仓库所有者 lotosbin 亲自提交（`4b8f5e5`，
    其后修复 `25926da`），该目录零未提交、与 `origin/main` 一致；临时兜底分支 `backup/npc-extension-v0.5.0-20261013`
    已按约定删除。**此后这条线的建议按正常 `bin2_extension` 口径走**（不再标 `待归属`）。
  - 其他/不确定 → 留空，由 @human 定。
- **一日多条建议**：每条占一行，不合并；合并之后就找不回来是哪个人提的。
- **快照与隐私**：评论/回帖会被删被改、链接会失效，所以出处可以是「链接 + 抓取到的原文快照文件」。
  但快照**只存原文 + 链接 + 抓取时间**，不要把整页 HTML 或大图塞进仓库；
  入库前**脱掉用户名/头像/uid 这类他人个人信息**——社区建议不需要带个人数据。
  小红书没有单条评论的固定链接，最小定位用「**笔记链接 + 评论 id + 原文首句**」。
  评论 id（DOM 里就是 `comment-<id>`）是**内容级定位符**，比"第几楼"稳——楼会被删、会变，id 不会。
  工具：`小红书分享/查看笔记评论.js`（**纯只读**：`--dump` 只输出 序号/评论 id/日期/原文，**不读昵称、uid、头像**）。
  读到的条数要与页面自报的「共 N 条评论」对账，**不一致时必须说明，不许默默截断**。

## 接 / 不接判据（技术侧，可拿去回答评论）

由 @bin2_extension_mod_dev 于 2026-10-13 给出，各渠道**可以直接引用**，不必每条都来问一次：

**接**：「原版某个东西玩家本来应该能自己做，但游戏里**没有任何路径**」——能说清游戏内名称或行为就行，不需要懂脚本。

**不接**（四条，也是 `已拒绝` 的理由口径）：
1. 改平衡数值（伤害 / 价格 / 掉率）；
2. 把别的模组整包合并；
3. 需要从零画美术；
4. **会形成材料循环的做法**。

**第 4 条的关键闸门（加配方前必查）**：能不能"回炉"？
**回炉产出 ≥ 配方消耗 = 拿 1 块料刷无限成品 → 一律拒**，并在表里写明理由。
1.7.0 那 5 条就是按这道闸过的（螺母螺栓无回炉标签、圆锯片按 1 金属板 = 4 钢块持平、螺丝产出 6 低于回炉门槛 10）。

**已有的「已拒绝」清单**（命中就直接判 `已拒绝`，不必重新讨论；出处：`bin2_b42/Changelog.txt` 1.7.0 段「刻意不做」）：
小手锯条（与手锯条重复且都能回炉）、纽扣（骨珠可替代）、武器刀刃 KillerBlades / `*_NoTang`（破坏锻造平衡）、
火柴与打火机（属于搜刮设计）、鱼 / 电子 / 带状态物品（`CandleLit`、`MetalPipe_Broken` 这类是设计如此）。

### ⚠ 使用这份判据前必须知道的数据边界

"真缺口"名单里**混着一类假阳性**：钓鱼、战利品、世界里能捡到的物件**没有建模**。
所以**不要拿名单直接当卖点**——照着念会念出"能不能做鲈鱼"这种笑话。任何方向都必须逐条核过再对外承诺。

## 四条"读起来像结论"的错（都比报错坏，写下来免得重复）

1. **AppleScript 的 `entire contents` 读辅助功能树不稳定——措辞是"不能信"，不是"必然欠计/不可比"**（被 @bin2_extension_mod_dev 两次纠正后定稿）：
   同一台机、同一页面（B 站直播页），**五种形态**：
   | 谁 / 何时 | 最前应用 | 路径 | 元素 | role 读到 | 失效 | AXButton | 耗时 |
   |---|---|---|---|---|---|---|---|
   | 组长 10:53:53 | 未记 | `entire contents` | 468 | 0 | 468（100%） | 0 | 9s |
   | mod_dev 10:54:54 | 未记 | `entire contents` | 469 | 314 | 155 | 2 | 53s |
   | mod_dev 10:55:59 | 未记 | `entire contents` | **209** | 209 | 0 | 16 | 26s |
   | 组长 10:57:07 | 未记 | `entire contents` | 381 | **0** | **381** | **0** | **8s** |
   | mod_dev 10:58:03 | **Safari** | `entire contents` | 383 | 381 | 2 | **13** | 37s |
   | mod_dev 10:58:03 | **Safari** | ctypes 直接 AX API | 385 | — | — | **13** | 0.07s |
   → **最后两行是决定性的反例**：同页同分钟，**两条路径给出的按钮数完全一致（13 = 13）**，路径 B 一点没欠计。
   **所以正确措辞是"不可靠"**：它**既可能完全一致，也可能全失效到 0**；写"跨路径不可比"会让下一个人
   **把真正的不一致当成正常现象放过去**，写"必然欠计"则是把反例当不存在。
   → **行动结论不变且更硬**：判"按钮在不在"**用直接 AX API**（0.07–0.15s，稳）；`entire contents` 只做回退，
   **且必须把"失效数"和按钮数一起报**（否则"欠计"看起来就像"没有按钮"——那场争论的起点）。
   → **未分开的变量（不要写机制）**：① 最前应用是谁 ② 窗口是否 `AXMain` ③ 页面活性 ④ **失效节奏**
   （8s 全失效 ~20ms/元素 vs 37s 几乎全成功 ~100ms/元素——"立即失败"与"走一半失败"可能是两种机制）。
   **要分开它们，用静态页**：下一篇 stage 好的发布页**不自动刷新**，是最合适的样本。
   实验设计（@bin2_extension_mod_dev 定，我采纳）：
   - **由把页面摆出来的人喊那一声**——发布页只能 @小红书运营 来 stage，**别人不该重开一张已发布的笔记**
     （会造出可能被误按的重复稿，他已经拒绝过一次，理由正确）；他摆好后**同一分钟喊两人**。
   - **四条读数交错跑：A、B、A、B，不要 A、A、B、B**。按组跑时，中间任何一次页面变化都会**伪装成"路径差异"**；
     交错跑才能让两条路径**共享同一个时刻窗口**（这也是 10:58 那组能定案的原因）。
   - **判据（@bin2_extension_mod_dev 提，我采纳并加一条前提）**：B 的读数**只有被 A 夹住才算数**——
     实际形态是 A1(0.1s) → B1(可能 8–53s) → A2(0.1s) → B2；**B1 合法当且仅当 A1 = A2**，
     A1 ≠ A2 时 B1 直接作废（那几十秒里页面动过，分不出"路径不稳"还是"时刻不同"）。A 只要 0.1s，正好当稳定期探针。
     **前提：A 不能只记"元素数 + 按钮数"**，必须同时落**这次解析到的窗口 id + 标签序号 + 该标签 URL**——
     定位条件一致才允许比较，否则窗口重排会被误判成"页面动过"，反过来把一张合法的 B1 判死。
   - **现场事实（组长 11:00 实测，与判据配套）**：Safari 侧三个窗口 `id=22287 tabs=3` / `id=8181 tabs=5` /
     **`id=6005 tabs=0`（隐形窗口）**，AX 侧只看到**两个**；不带 `try` 的枚举被那个 0 标签窗口整段打断
     （`-1700`，**脚本返回空、先前窗口的读数一起丢**，当天两次）。**发布页当时是后台标签**
     （`publish/publish` 在 win 22287，而该窗口当前标签是 `live.bilibili.com/8392646`），
     **最前应用是 DeepSeek Harness、不是 Safari**。
     → 「把页面摆出来」这个动作**包括**"把它调成当前标签，并当场核一句它的 URL"；
       「最前应用 / `AXMain`」只能当**变量**记，不能当"页面就在眼前"的证据。
   - 三个变量各归能记的人：**"页面有没有在动"只有摆页面的人能记**；最前应用、是否 `AXMain` 由读数的人一并打出。
   - 路径 A 探针：`notes/verification/axcount.py`（组长，纯只读）。
   → ⚠ 我在这条上**改过两次措辞、错了两次**（先说"量不了 `role`"，再说"跨路径不可比/必然欠计"），
   **两次都是拿一次读数给整条路径下定义**——与 A3 同源，见 `docs/develop_log_2026-10-13.md` 第七节。

2. **一个 0 标签页的隐形窗口会让整段枚举变成零输出（可复现，我实测两次）**：
   本机 Safari 侧有 **3 个窗口**，其中 `id=6005` 是 **0 标签页、`visible=false`** 的隐形窗口；
   而 AX 层和 System Events 都只看到 **2 个**。不带 `try` 遍历 `URL of current tab of window i`：
   ```
   execution error: 不能将"URL of …window 3…"转换为"Unicode text"类型。 (-1700)
   ```
   **整段脚本一条都不返回**——前两个正常窗口的结果也一起丢掉。这与 `axPublishButtonState()` 的 ①（`ERR → 'no'`）同路。
   → 修法很小：**`URL of current tab` 一律包 `try`**，并把"读不到"与"读到的是别的页"分开报。

3. **同一个报错文案被三种情况共用**（@小红书运营 查出，**我读源码复核确认**）：`axPublishButtonState()` 在三种情况下
   都返回 `state:'no'` —— ① `osa` 抛错/超时（`out==='ERR'`）② `pubWins` 为空**且** `publishWindowIndex()` 也找不到
   （**发布页不在任何标签里**）③ `pubWins` 含窗口 1（发布页是当前标签页、树里却没有按钮）。
   而渲染层把这三种都打成**同一句** `× …树里没有 AXButton「发布」`。
   → **后果比"误报"更糟**：我 10:34/10:35 那两次 `×` 读数**连属于哪一种都无法判定**，我却把它当成了"按钮不在"的单一结论。
   **含糊的状态词会让人在无法判定的地方下一个确定的结论。**
   → 正解：拆成 `absent` / `timeout` / `tree-missing-button` 三态，文案只陈述各自成立的前提。
   → 这条也**彻底关掉了"工具指错窗口"那个断言**：该函数在把某窗口算作"发布页窗口"前**先核对它的当前标签页 URL
   含 `publish/publish`**，不会按序号乱认；我 10:45:44 读到 `unraised`（发布页在第 2 个窗口）说明那一刻**窗口 2 的当前标签页
   确实是发布页**，到 10:46:38 它是 B 站直播 —— **只能是目标移动，不可能是指错窗口**。
4. **复用标签页不重新加载，会输出"带新时间戳的旧数据"**：`查看笔记评论.js --profile` 复用标签时没有 `location.reload()`，
   于是连续两次都报"30 条"、**新笔记根本不在列表里**，而输出上还打着「读数时间 = 现在」。
   → **这比报错坏**：报错会让人去查，而它给人一个看起来确凿的错答案。已改成复用先 `reload()` 并等 `readyState==='complete'`。
   → 通则：**读数不仅要有时间戳，还要能证明底层数据是重新取的**——时间戳只能证明"我这一刻打印了"，不能证明"我这一刻重新读了"。

## 平台发布的两条坑（发帖的人踩过，写下来免得重复）

1. **B 站动态：点「发布」不等于发出。** 网页端会再弹一个「确认并发送」的规范弹窗，**必须再点它才落库**。
   @哔哩哔哩运营 第一次点完「发布」后接口里查不到新动态，正是缺这一步（`控制台/发动态.js --send` 已补）。
   —— 这是同一类病的第 N 次复发：**操作返回成功 ≠ 状态已改变**，必须回读目标状态才能宣称成功。
2. **B 站列表接口不下发正文。** `x/polymer/web-dynamic/v1/feed/space` 对图文动态**不含 `desc.text`**，
   只看列表会把一条有内容的动态误判成空动态；**要读正文得用 `x/polymer/web-dynamic/v1/detail`**。
   （判据是本机实测的接口行为，属"会变的状态"，引用前按规矩 A 重读。）

### 各平台的"我能不能独立核到"（2026-10-13 实测，供后来者少走弯路）

| 平台 | 无登录态能否核到内容 | 说明 |
|---|---|---|
| 小红书（笔记页） | **能**（裸 HTTP 即可） | 200 + `<title>` + 正文关键词 |
| B 站（动态 / 专栏） | **只在浏览器上下文里能** | 见下，别照抄"核不到"三个字 |
| QQ 频道 / QQ 群 | **不能** | 只有 JS 壳，内容前端渲染；群回复连接口都没有 |

**B 站那条要按实测口径写，不然会误伤**（@哔哩哔哩运营 复议 + 我复现 curl 侧）：

- **浏览器内、不带 cookie** 请求 `x/polymer/web-dynamic/v1/detail?id=…` → **HTTP 200 / `code:0`**，
  响应里有**完整正文**（他实测首句 / 中段 / 末句 5/5 命中）与 `visible:true`；**不是缓存**（加时间戳强制新请求仍成立，
  同一时刻带 cookie 的响应更大 185 字节，属字段裁剪而非内容不同）。
- **裸 `curl` 一律 `{"code":-352}`**（我复现过，换 Safari UA、带 Referer 无效），网页版只有 3.5 KB 前端壳页。
- **两边不矛盾**：区别在于**请求带不带浏览器的风控指纹**（UA / Referer / buvid 那类）。
  所以正确表述是：**离开浏览器核不到，原因是风控不进门，不是内容不可见。**

> ⚠ 别拿网页壳页当"看不到"的证据：动态正文本来由 JS 拉，壳页不渲染正文，**与可见性无关**。

**所以对外结论只有两档**：①「我独立核到」（附读数时间 + 命令）②「采信执行者在浏览器上下文里的回读证据」（写明是谁、读到什么）。
**B 站与 QQ 渠道归第②档**——这既没把证据说小，也没把边界说大。

> # 扫全部对象（含 dangling）→ 1

> # 要 blob id（慢但直白，约 37s）→ da911197bfe9882c49008610192c8fb6f0c779a4
> git cat-file --batch-all-objects --batch-check | awk '$2=="blob"{print $1}' \
