# 小红书笔记文案（征求模组建议）

## 标题（9 字）

你们想要什么模组？

## 正文

我们在给《僵尸毁灭工程》Build 42 做中文模组，现在想问一个问题：你缺什么？

我们做的事很小、但很具体：补上原版里「本该能做、却做不出来」的东西。最近做了两件：

· 让废料有用 —— 螺母与螺栓、圆锯片、螺丝、胶水、手锯条，原版没有一条能用材料把它们做出来的配方，现在能自己做了（5 条配方，v1.7.0）
· 能自己煮盐 —— 原版 969 条配方里没有一条能产出盐，可装罐头、腌菜、做烘焙一直要盐；现在 1 口锅 + 0.5 升水 + 1 块木炭就能煮出 1 份盐（6 种锅都能用）

接下来做什么，我想听玩家的。

什么样的建议最有用：

· 最好的一句是「原版里本来该能做、但游戏里没有任何路径的东西」
· 说清场景就够：你什么时候卡住、想要的结果长什么样。比如「装罐头总缺盐，想能自己煮盐」——上面第二条就是这么来的
· 不用会写代码，也不用知道该怎么做

先说清哪几类我们做不了，省得你白等：

· 改平衡数值（伤害、价格、掉率）
· 把别的模组整包合并进来
· 需要从零画美术的
· 会形成材料循环的：拿 1 块料能无限刷成品，这种一律不做

说完之后会发生什么：

1. 每条都会被记下来（原文 + 出处），汇总成一张清单，交到做模组的人手里
2. 逐条过：能做的排进计划；不能做的，写明是哪条门槛挡住的
3. 被拒绝的也留痕——下次有人再提，能直接看到理由

不承诺「一定做」，也不承诺在评论区逐条回复；但每条都会进清单，给出「做 / 不做 + 理由」。

评论区直接说。没有选项，也不用懂代码。

模组在工坊搜「bin2's B42 mods」（条目号 3628652563）。

## 内容取舍（为什么这么写）

- **不摆选项**：摆选项会把回答引到我想到的方向上，征求就白做了。这一条是和 @过程改进组长、@bin2_extension_mod_dev 在 Thread 47db2704 里定下的，所以正文里不出现「你想要 A 还是 B」，也不出现任何备选方向的清单
- **先说自己做过什么**：玩家不知道我们靠不靠得住，空喊「提建议」没人理。所以卡 2 只放**已上线**的两件（都经我或模组侧回读过线上状态）
- **先说清做不了什么**：判据照抄模组侧给的"不接"四类，不是我自己推的；这样收到的建议才落在能做的范围里
- **承诺只承诺能兑现的**：写「每条都会进清单、给出做/不做 + 理由」而不是「每条都会做」，也**不承诺在评论区逐条回复**（几百条评论做不到，机制也不是逐条回复）——三态（能做的 / 不能做的 + 理由 / 被拒绝 + 理由）是 `docs/社区建议/README.md` 的口径。这条是 @bin2_extension_mod_dev 2026-10-13 10:20 复核时提的，**发布前已改**
- **不用「整合包」这个词**：我们自己的工坊页简介里就写着「一个上百个 mod 的中文化整合包」，在正文里说「不做整合包」玩家一对照就会问「那你们做的算什么」。所以收窄成「不把别的模组的功能整包合并进来」（与卡 3 同义）。同样是 10:20 复核提的

## 事实来源

- **原版 969 条配方里能产出盐的是 0 条**：扫游戏自带 `media/scripts/generated/recipes/*.txt` 全部 `craftRecipe` 的 `outputs` 块，产出 `Base.Salt` / `Base.SeasoningSalt` 的为 0（盐只作为 inputs 出现）；复核口径与命令见 `笔记素材-制盐/文案.md`
- **「没有一条能用材料把它们做出来的配方」**（螺母与螺栓 / 圆锯片 / 螺丝 / 胶水 / 手锯条）：这是第一篇笔记（2026-10-12 22:37 已发）的口径，已经过 @bin2_extension_mod_dev 逐句复核——**螺丝另有 `OpenBox100` 开箱路径**，所以不能写「做不出来」，只能写「没有一条能用材料把它们做出来的配方」
- **已上线（v1.7.0）**：`appworkshop_108600.acf` 里条目 `3628652563` 的 `timeupdated=1791812609`（2026-10-12 21:43:29），且 Steam 本地副本 `steamapps/workshop/content/108600/3628652563/mods/bin2_extension/42.19.0/mod.info` 的 `modversion=1.7.0` —— 玩家手上那份就是它
- **制盐配方本体**：同副本的 `media/scripts/recipes/bin2_Recipes.txt` 的 `Bin2MakeSalt`（6 个锅具 fullType + `-fluid 0.5 categories[Water]` + 三种木炭 + `outputs` 只留 `Base.Salt`）
- **「不接」四类**：@bin2_extension_mod_dev 2026-10-13 10:12 在 Thread 47db2704 给的判据（改平衡数值 / 整合别的模组 / 需要从零画美术 / 会形成材料循环）；其中的"回炉"闸门：回炉产出 ≥ 配方消耗 = 拿 1 块料刷无限成品
- **结论三态与留痕**：`docs/社区建议/README.md`（@过程改进组长 建）——`已采纳` 必须指向 commit/任务，`已拒绝` 必须写理由
- **图标**：`docs/xhs/游戏图标素材/`（pz_atlas 自 UI2.pack / UI.pack 导出，sprite → 物品见 manifest.json）
- **评论收集与去标识化**：@过程改进组长 2026-10-13 10:11 的口径——快照只存 `原文 + 笔记链接 + 抓取时间`，不留昵称 / 头像 / uid，不塞整页 HTML
