版本 0.1.1 (2026-10-05)
- 修复（玩家实测反馈：按钮/文字错位）：
  1. 招募面板右侧的说明文字会压住「跟随/守卫/居民」按钮行（窗口越矮越明显）。
     原因：模式按钮固定在 `listTop + 118`，而文本从上往下不限行数地画。
     修法：右侧面板改成**自下而上**排版 —— 先从底部预留「模式行 + 主按钮 + 次按钮」两块固定高度，
     文本区夹在中间，`render` 只画得下的行（宁可少画一行，也不压控件）。
     次按钮位即使当前页签用不到也**照样预留**，所以切页签时按钮不再跳。
  2. 首页入口按钮会与橙子经济自己的「卡片」视图按钮重叠（两个标题叠成「NPC 招募: 卡片」）。
     原因：原实现只把「社区中心」按钮当锚点，而它在社区中心功能关闭时根本不存在，
     于是回退到"贴右边缘"，正好压住右侧那排视图切换按钮。
     修法：把「社区中心 / 概览首页 / 卡片」三个锚点都收集起来取**最左**，贴在它左侧；
     一个都没有时贴左边缘，绝不与右侧控件抢位。
- 新增回归测试：把版面几何当契约来测（800x600 / 1200x700 / 520x420 三种尺寸下断言
  文本区止于模式行上方、按钮两两不重叠、全部落在页面内、小窗口 render 不抛错）。
  已做过失败实验：把文本裁剪改回旧行为，三条断言立刻变红。
- 版本号 0.1.0 → 0.1.1（mod.info / Config.VERSION / 工坊简介）
- 已发布工坊：id=3813914438（public）；简介里的依赖改写成可点击的 [url=…] 链接
  （Steam 的「必需物品」只能在网页手填 —— workshop.txt 没有依赖键，实测追加 required= 会被静默忽略）

版本 0.1.0 (2026-10-05)
- 初始版本：为「橙子社区经济」增加 NPC 招募功能，兼容 Project A-Life Jeem Extension
- 功能：
  * 招募面板（`OrangeTradingMod.UIPageRegistry` 公开页面 API 注册，页面 id `bin2NpcRecruit`）
    与首页入口按钮；另加 Ctrl+Alt+N 热键（该模组自身全库没有任何按键绑定，不会冲突）
  * 收编：花钱把身边已有的 A-Life NPC 签下来（服务端校验距离/名额/归属/敌对）
  * 中介派遣：`ActorRegistry.create` + `SpawnService.request` 现造一名友好 NPC；
    生成失败自动全额退款，不会出现「花了钱没人」
  * 三种岗位：跟随（A-Life 原生 follow）/ 守卫（hold + 锚点）/ 居民（Jeem `Residents.recruit`）
  * 名册：切换岗位、解雇、阵亡自动释放名额、日薪与欠薪宽限期
- 依赖：必需 `OrangeCommunityEconomy`；需要 `ProjectALifeNPCs`；可选 `ProjectALifeJimmy`
- 安全设计：
  * 钱只走 `OrangeTradingModServer.Pay` / `AddCoins`（服务端权威，客户端不传价格）
  * 自带限速与 requestId 去重（橙子经济的 action_request_guard 是白名单制，第三方塞不进去）
  * 防人口回收：雇佣期间给 NPC 写 `memory.persistent` + `memory.admin.persistent`
  * 读档后自动重下 follow/hold 指令（A-Life 的 orders 是内存表，不持久化）
  * 改动状态一律先扣款后落地，失败按路径退款或降级（降级会写进契约备注并显示在面板上）
- 未修改任何第三方文件；不带任何 A-Life / Jeem 的 Lua 副本；不占用它们的网络 module
- 已知限制：
  * 尚未在游戏中完整跑过验证（只做了 Lua 语法检查 + 离线逻辑测试 + 工坊探针校验）
  * Jeem 的居民招募按「小队」收编，转居民时可能把整支小队带进营地
  * 与其它 NPC 模组（Bandits2 等）的共存未测试
  * 未做真实上传验证；`workshop.txt` 首次上传不带 `id=`，`visibility=private`，验证无误后再改 public
