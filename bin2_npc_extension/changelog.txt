版本 0.5.2 (2026-10-19)
- 新增（玩家需求）：**在世界里对着 A-Life NPC 右键就能收编** —— 「收编 <名字>」→ 直接走服务端收编
  （金额 / 名额 / 距离 / 敌对全在服务端校验，结果照旧用提示弹出来）
  * 为什么：玩家原话「招募中立 NPC 放到右键菜单中，现在 NPC 跑太快来不及招募」。以前只有一条路：
    Ctrl+Alt+N 开面板 → 切「收编」→ 点「扫描附近」→ 在列表里找那个人 → 选中 → 收编；
    NPC 在走，这一串做完他可能已经出了 `RecruitRadius`
  * 条目的位置：**插在 Project A-Life 自己的 `[A-LIFE] …` 条目之后**（没有就追加在末尾），
    不用把鼠标滚到菜单最底下
  * 半径 = 沙盒的 `RecruitRadius`（默认 6，与面板「扫描附近」和服务端校验**同一个值**）；
    名单复用 `Alife.candidates`，所以右键里能点的人与面板里能收编的人永远是同一批
  * 人多时收进子菜单 `[bin2] NPC 招募`（每人一条、带整数米距离、最多 4 条）；
    已经雇着的人 / 别人雇走的人 / 敌人 / 已是 Jeem 居民 / 前哨驻军 都不会出现
  * 岗位取沙盒 `DefaultMode`（与面板收编按钮不选岗位时一致）；想改成别的岗位仍可开面板
  * 只服务 player 0（本模组其它客户端入口都是），分屏 1P 之外不抢别人的菜单
  * 实现放在**公共层**（`Bin2NPCExtensionCore/Context.lua`，手写文件，三个口味共用）；
    只 `Add` 一个 `Events.OnFillWorldObjectContextMenu` 监听器，**不去包** `createMenu`
    （两边经济模组的 UI 宿主都包过它，再包一层就是叠套娃）
  * 顺手给第一人称模组（Viewpoint 这类按"光标下的对象"过滤条目的）把 NPC 的 shell 塞进 `param10`，
    否则那条会被人家的菜单筛掉
- 离线测试（不需要游戏，fengari）
  * 新增 3 条用例：右键点在人旁边 → 条目出现、点它按 `DefaultMode` 收编、钱按 `SignPrice` 扣；
    半径跟着沙盒走（`RecruitRadius=2` 时 3 格外的看不见，调大又回来）；人多→一个子菜单（最近的在最前、
    带距离、上限 4 条）；同一张菜单不会被填第二遍；空地/分屏 1P/沙盒关掉 都不加条目
  * mock 补了 `Events.OnFillWorldObjectContextMenu`、`ISContextMenu.getNew`、右键菜单对象与"光标下的对象"

版本 0.5.1 (2026-10-18)
- 修复（工坊反馈）：把**跟随/站岗中的雇员**改成「居民」后，他仍然跟着你 / 一直站在锚点上
  * 根因一：转居民成功时没有清掉我们下给 A-Life 的 `follow`/`hold` 命令。`DecisionLoop.orders`
    是**持久意图**不是一次性动作；而契约变成"居民"之后 Maintain 的 8 秒重下不再跑，
    于是**没有任何东西会再清理它** —— 玩家看到的正是"选了居民，人还跟着我"
  * 根因二：`Jimmy.residentEntry` / `canManage` 以前把"问不到"（上游改了签名、记录形状变了、
    拿不到 who）和"不是居民"混在一起。一旦读成"不是居民"，对账会把居民岗位**降级成跟随**，
    再每 8 秒重下一次 follow —— 与基地控制器那类模组抢人
  * 现在：转居民（含"他已经是居民"的幂等路径、Jeem 回 `resident`、同小队一起入住）统一收尾并
    `Alife.clearOrder`；Maintain 每个 tick 多一条红线 —— 事实是居民就**不下**任何跟随/站岗命令；
    两个判断都改成三态（`值, 是否问到了`），**问不到时什么都不改**
  * 顺带：`canManage` 问不到时不再写「这不是你的基地」这种假说明
  * 热键不是原因：本模组**只注册一个按键** `Ctrl+Alt+N`（自己查修饰键，不写游戏的 Bind 表）
- 离线测试（不需要游戏，fengari）
  * 居民岗位的新断言：跟随中的雇员转居民 → 命令被清空；旧存档分叉（契约写跟随、事实是居民）
    → 下一 tick 按事实纠正、且一条命令都不下；解雇路径的 `forget` 计数相应变成两次
  * 三套：橙子 46/46、YeseMarket 46/46、原版钞票 50/50
- 工具：`tools/extract_base.py` 加了**手改基线**（`HAND_EDITS` = 文件 → sha256 + 原因）：
  `--check` 仍会红 —— 未登记的手改、登记后又被改，两种都报；`--print-hashes` 打印当前哈希

  * 根因：生成器里那条"把兄弟 id 翻成对方"的替换，紧接着又被全局替换切了一次

- 测试：离线断言从 39 条增加到 **40 条**（新增"公共层接口版本校验"；用例 34 增加 sibling 自指回归）
  * 同时修正了测试驱动的保真度：旧驱动用 dofile 加载被测文件却不登记 `package.loaded`，

版本 0.2.3 (2026-10-05)
- 修复：**面板把队友误报成「居民化被拒」并降级为跟随**（截图里那句
  「居民化被拒（resident（上游返回）），已降级为跟随」）
  * 现象：一栏雇员明明已经是营地的居民（在打水、巡逻、被基地保护），面板上却写着「岗位：跟随」，
    再点「居民」还被拒
  * 根因：面板右下角「应用岗位」发的就是"当前岗位"（`mode = pendingMode or contract.mode`），
    而岗位按钮当时是点一下立刻发 SetMode —— 于是"对已经是居民的人再应用一次居民"
    等于请求 Jeem 再收编一次。Jeem 的 `Residents.recruit` 对已经住进来的人会回
    `resident`（`Features/Residents/Server.lua:577`，真实含义是"**他已经是居民了**"），
    我们把它当失败处理：把契约降级成 follow、写上 note `resident:resident`，
    而且**写坏了缓存** —— 之后 `setMode` 只在"缓存说自己是居民"时才调 `leaveOne`，

  * 修法五（文案）：`Text.lua` 穷举 Jeem 的拒绝码（resident / not_allied / no_beds / …），
